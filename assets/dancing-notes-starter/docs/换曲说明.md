# 换曲时，哪些东西必须重新生成？

不是只换音频文件。必须同时准备：

1. public/score/score.svg：新MXL渲染结果，保留稳定note ID。
2. public/score/piano.wav：与新MIDI时间一致的音频，不预加开场静音。
3. src/score-data.json：新曲标题、SVG尺寸、事件、坐标、时长与镜头路径。

## 建议流水线

    python3 scripts/read-music.py 自己的曲谱.mxl 自己的音乐.mid output/analysis
    node scripts/engrave.mjs output/analysis/identified.musicxml output/engraved
    node scripts/note-geometry.mjs output/engraved/page-1.svg output/geometry.json

浏览器由Remotion工具启动，第一次可能需要下载。engrave会导出所有页，不会默认把第一页面当作整首。SVG坐标只对应本次渲染，改排版必须重取坐标。

单页使用时，将 `output/engraved/page-1.svg` 复制为 `public/score/score.svg`，并将自己生成的已对齐音轨放为 `public/score/piano.wav`。多页先按上述规则处理，坐标提取必须对应最终使用的SVG。

接下来由Agent读取 `output/analysis/music-analysis.json` 与 `output/geometry.json`，生成符合src/types.ts的JSON：

- 用拍位置＋音高＋声部/voice匹配；同音高并发事件逐一对应，不无条件取第一个。
- MIDI所有正力度起音都进入events，每项有唯一eventId。
- activations包括每个起音，以及需要显示的tie延续符头。每个events项须与同eventId的attack activation保持时间、时长、力度、音高、谱表、system、scoreId和坐标一致（浮点误差容许1e-6）；额外的sustain使用独立eventId，不需要伪造MIDI起音。
- scoreId指真实SVG符头，x/y来自该符头的几何中心。
- 颤音展开可多次对应同一符头；每次的eventId不同。同一符头按最新触发重置ring。
- 倚音使用MIDI实际时间，不能按谱面零时值把它们挤到同一时刻。
- 音符system从0编号；不是MIDI track/channel。
- time和duration单位秒，以原音乐时间0为起点，不含开场5帧。
- staff为1或2，velocity为MIDI力度，kind用attack/sustain。
- SVG宽高来自viewBox；不能拿截图像素代替。
- musicDuration为实际选定音乐范围的长度，无10秒或两行限制。
- 标题和作曲者用数据字段设置，不写进渲染器。

## camera字段

camera是按时间严格递增的 {time,x,y} 数组：
- time为音乐秒；
- x/y为SVG坐标（渲染器再乘scoreScale）；
- y通常取正在演奏的上下谱表之间；
- 包括开头预备段、末尾和换行过渡所需的关键位置；
- 换行需根据实际休止/持续演奏重新设计，不能复制其他曲子的秒数。

先用少量关键帧检查球体、和弦、谱表上下边界，再渲染短视频。完整曲目还要检查每次换行和换页，不要仅验证第一行。

## 必须报告

Upper/Lower各自的MIDI事件数、成功映射数、未匹配事件；延音和装饰音单独说明。validate脚本只做结构检查，不能证明音乐映射正确。

音轨与动画要分别验证：检查起点、多个中间起音和结尾，确认没有逐渐漂移、重复入场延迟或削波。
